## 1. 需求规格说明书

### 1.1 产品定义与非目标

| 项 | 内容 |
|---|---|
| 一句话 | 把一份 Markdown 解析成卡片树，在可缩放白板中做非线性阅读的 Windows 只读桌面工具 |
| 目标用户 | 写作者、研究者、学生、开发者；阅读长技术文档/论文笔记/教程/项目文档，需在章节、代码、图表间来回对照的人 |
| 核心价值 | 消除"读后面要回看前面"带来的滚动与新开窗口成本，且不破坏"Markdown 文件是唯一内容源" |
| 非目标 | 编辑 Markdown；热更新/监听；协同；云同步；版本控制；自动智能布局；非 Mermaid 图表；任务列表回写；多窗口同步 |

### 1.2 术语表

| 术语 | 定义 |
|---|---|
| 文档 | 一个被打开的 `.md` 文件 |
| 块（IR） | Markdown 解析出的块级元素，**包含不成卡的**段落/引用/普通列表 |
| 卡片 | 由块生成的独立可视化单元；有边框、标题栏、类型图标、选中/拖拽态 |
| 大卡片 | 顶层容器卡片，由分隔线划分；无分隔线时整篇为一个大卡片 |
| 卡片树 | 大卡片 → 标题卡片（H1 ⊃ H2 ⊃ H3 …）→ 其他块级卡片 |
| 自有内容 | 归属于某卡片但不单独成卡的块及其行内元素（加粗/链接/行内码/行内公式） |
| 白板 | 承载全部卡片与连线的可缩放画布 |
| 自由卡片 | `detached=True` 的卡片：脱离父卡片几何约束、可在白板内自由拖动，**逻辑父子关系仍保留** |
| 布局快照 | 坐标、尺寸、z 序、折叠、detached、视口缩放/平移、窗口状态 |

### 1.3 功能需求

#### FR-1 解析与卡片化

- FR-1.1 解析器输出两层结果：**块序列 IR**（唯一中间真相）+ **卡片树**。渲染层不得再次解析原文。
- FR-1.2 成卡类型 ✅：标题（H1–H6）、图片、代码块（含语言）、表格、块级公式、Mermaid、任务列表、目录。
- FR-1.3 不成卡类型 ✅：普通段落、引用、普通有序/无序列表 → 作为所属卡片的"自有内容"完整保留（不丢原文，行内元素照常渲染）。
- FR-1.4 分隔线 ✅ 本身不渲染为卡片，只作大卡片分界。
- FR-1.5 任一卡片解析/渲染失败 → 该卡片降级为纯文本卡片 + 可见错误标记；不得中断整篇解析或崩溃（验收 10）。
- FR-1.6 编码与换行：显式处理 UTF-8 / UTF-8-BOM / GBK 探测与 CRLF/LF；解码失败 → 提示 + 降级纯文本卡片 🔶。
- FR-1.7 图片路径：相对路径以 **Markdown 文件所在目录**为基准；缺失图片 → 可见占位符，不阻塞。远程图片默认不加载 ❓（O4）。

#### FR-2 卡片嵌套关系

- FR-2.1 大卡片为顶层容器；标题卡片按层级形成父子关系 ✅。
- FR-2.2 其他块级卡片归属于**最近的上级标题**；无标题时归属当前大卡片 ✅。
- FR-2.3 卡片自有内容 = 仅直属块（✅ D5）。
- FR-2.4 卡片树支持折叠/展开、选中、定位；目录卡片点击 → 跳转/聚焦对应标题卡片 ✅；目标在折叠祖先内时先展开祖先并提示路径 🔶。
- FR-2.5 边界规则见 §2.3（🔶 提案）。

#### FR-3 白板与初始布局

- FR-3.1 首次打开按文档原始顺序**自上而下线性排列**，并保持嵌套关系 ✅。
- FR-3.2 白板支持缩放、平移、适应视图 ✅。
- FR-3.3 缩放 = **整体画布变换**（卡片尺寸与文字一起缩放）✅；滚轮以光标为锚点，输入百分比以视口中心为锚点 🔶。
- FR-3.4 卡片可自由拖动；默认子卡片被约束在父卡片内 ✅；拖动父卡片时子卡片跟随 ✅（D8），`detached` 子卡片不跟随。
- FR-3.5 视觉边界：边框/阴影/标题栏/类型图标/选中态/拖拽态 ✅。
- FR-3.6 布局持久化，重开后恢复 ✅。
- FR-3.7 折叠 ✅（D6）：隐藏子孙卡片并收缩父卡，子卡位置被记住；展开后位置还原。

#### FR-4 拖出与还原

- FR-4.1 默认子卡片不可直接拖出父卡片 ✅。
- FR-4.2 右键 →「拖出为自由卡片」：`detached=True`，脱离父卡几何约束，可自由移动；**逻辑父子关系保留** ✅。
- FR-4.3 自由卡片可再次拖动、缩放、折叠 ✅。
- FR-4.4 右键 →「还原到父卡片」；父卡右键 →「收回所有子卡片」✅。
- FR-4.5 右下角「全部还原」：所有卡片回到初始线性排列、清除拆出状态 ✅（是否同时重置视口缩放 ❓ O4）。
- FR-4.6 还原按原 Markdown 顺序插回原父卡片/原位置 ✅。
- FR-4.7 父卡片在子卡 detached 期间被删除/重归属 → 定义为"孤儿自由卡片"：挂到最近存活祖先，无则挂顶层，并提示 🔶。

#### FR-5 刷新（结构优先重建）

- FR-5.1 不自动监听、无热更新；仅右下角按钮触发 ✅。
- FR-5.2 刷新 = 重新读取 + 重新解析（同一路径）✅；读取失败 → 保留当前卡片树 + 报错，不重建。
- FR-5.3 三级策略 ✅：
  1. 结构未重大变化 → 尽量保留位置、缩放、折叠、detached；
  2. 结构重大变化 → 以新结构重建，**显式提示**旧位置可能丢失；
  3. 无法匹配 → 以新结构为准重建，**禁止静默丢弃用户布局或内容**。
- FR-5.4 重大变化判据 ✅（D11）：**大卡片数量变化** 或 **标题层级序列变化**；正文改写、卡片内容增删不算重大。
- FR-5.5 新卡片按新文档顺序插入对应父卡片；删除卡片移除或标记失效，其子卡按新结构重归属 ✅。
- FR-5.6 匹配键 ✅（D4）：`stable_key` 为主，`content_hash` 仅用于变更检测（§2.4）。

#### FR-6 多窗口

- FR-6.1 支持多开窗口；每窗口可打开不同或不相同的文件 ✅。
- FR-6.2 窗口之间布局、刷新、拆出状态**完全独立**、不自动同步 ✅。
- FR-6.3 进程模型 ✅（D10）：**多进程，每窗口一个进程**。共享与不共享的边界：🔶 不共享任何可变布局状态；解析缓存可各进程独立（无需共享）。跨进程窗口注册用于"重开恢复"，实现方式 ❓ O4。

#### FR-7 文件与状态持久化

- FR-7.1 打开本地 Markdown 文件（文件对话框；命令行参数与拖入 ❓ O4）。
- FR-7.2 布局状态存应用数据目录，**不放 Markdown 同目录** ✅。🔶 提案：状态 → `%APPDATA%\MarkdownCardWhiteboardReader\`；缓存/Web 资源 → `%LOCALAPPDATA%\MarkdownCardWhiteboardReader\Cache\`。
- FR-7.3 保存内容 ✅：卡片坐标、尺寸、z-index、折叠状态、detached 状态、视口缩放/平移、窗口状态。
- FR-7.4 ✅（D9）每文档一份 JSON；写入必须**原子**（临时文件 + `os.replace`）并带 `schema_version`；快照损坏 → 降级为"仅重建布局" + 提示，不得阻塞打开。
- FR-7.5 多进程打开同一文档 ✅（D15）：每会话一份快照分片 + `last_session` 指针，互不覆盖。

#### FR-8 只读保证

- FR-8.1 应用对源文件及其同目录**零写入** ✅；日志、缓存、临时文件一律不得落在该目录 🔶。
- FR-8.2 可测判据：打开前后源目录的文件集合与各文件 mtime 不变（集成测试断言）。

#### FR-9 辅助交互（版本归属 ✅ D12）

- MVP：折叠/展开。
- 后续：搜索并定位卡片、大纲导航、父子连接线、快捷键、复制代码、图片缩放、表格滚动、任务列表只读渲染精化。
- 任务列表**不回写** Markdown ✅。

## 2. 核心数据模型

> 领域层为纯 `dataclass` / `enum`：零 IO、零框架、零 GUI 依赖。GUI 与持久化只能通过 DTO 转换接触它们。

### 2.1 实体

**Block（IR，文档中每个块级元素都有一条）**

| 字段 | 类型 | 说明 |
|---|---|---|
| `index` | `int` | 文档原始顺序（0 起），是"不丢原文"与 insertion 的基准 |
| `kind` | `BlockKind` | `heading / paragraph / blockquote / list / task_list / table / code / math_block / mermaid / image / toc / thematic_break / html / unknown` |
| `level` | `int \| None` | 标题层级 H1–H6 |
| `lang` | `str \| None` | 代码块语言 / Mermaid |
| `raw_text` | `str` | 原文片段（降级渲染的兜底） |
| `text_normalized` | `str` | 规范化文本（统一换行、压缩空白），仅用于内容指纹 |
| `inline` | `tuple[InlineSpan, ...]` | 加粗/链接/行内码/行内公式等行内元素 |
| `span` | `SourceSpan` | 行号区间，供定位/回跳原文件 |

**Card**

| 字段 | 类型 | 说明 |
|---|---|---|
| `card_id` | `CardId` | = `stable_key`（见 §2.4） |
| `kind` | `CardKind` | `big_section / heading / image / code / table / math_block / mermaid / task_list / toc / fallback_text` |
| `parent_id` | `CardId \| None` | 逻辑父卡片；`detached` 不改变此值 |
| `child_ids` | `tuple[CardId, ...]` | 文档顺序 |
| `own_block_indexes` | `tuple[int, ...]` | **自有内容**（D5：仅直属块） |
| `heading_path` | `tuple[str, ...]` | 标题路径，stable_key 组成部分 |
| `ordinal_in_parent` | `int` | 同级序号，处理同名标题 |
| `content_hash` | `str` | 规范化内容指纹；仅用于变更检测/缓存失效，**不参与身份** |
| `rendered` | `RenderedContent \| None` | 渲染产物引用或内联片段（可空 = 未渲染/降级） |

**CardLayout（几何与视图状态，与 Card 分离）**

| 字段 | 说明 |
|---|---|
| `card_id` | 关联键 |
| `x, y` | 白板坐标（**白板坐标是唯一几何真相**） |
| `w, h` | 尺寸 |
| `z` | 层级顺序 |
| `collapsed` | 折叠（D6：隐藏子孙、父卡收缩、记忆子卡位置） |
| `detached` | 是否自由卡片 |
| `manual_size` | 🔶 用户是否手动改过尺寸（决定是否参与自动布局重算） |

**Viewport**：`scale: float`、`pan_x/pan_y: float`、`fitted_once: bool`
**WindowState**：`window_uuid`、`geometry`、`open_documents`、`active_document`、`process_id` 🔶
**BoardSnapshot（持久化单元）**：`schema_version: int`、`document_key`（`path_hash` + `size` + `mtime` + `content_hash`）、`layouts: dict[CardId, CardLayout]`、`viewport`、`window_ref`

### 2.2 不变量（必须由单测守卫）

1. 每张卡片恰有一个父卡片或为大卡片 → 树而非图。
2. `own_block_indexes` ∪ 全覆盖 IR 的全部 `index`，无遗漏、无重复 → **「不丢失原文」的可测判据**。
3. 子卡片几何位于父卡片边界内，除非 `detached=True`。
4. `detached=True` 不改变 `parent_id` / `child_ids`（逻辑树与几何解耦）。
5. 标题卡：子标题 `level` > 父标题 `level`。
6. 任何快照可反序列化为等价 `BoardSnapshot`，或安全降级为空布局（不得抛错崩溃）。
7. 拖动/还原是幂等状态机：`还原(拖出(x)) ≡ x`（几何按规则重算后一致）。

### 2.3 卡片树构建规则（🔶 提案，未经确认不得视为需求）

1. 先按 `thematic_break` 切分大卡片区间；文档开头无分隔线的内容并入首个大卡片；连续分隔线**不产生空大卡片**。
2. 每个区间内用标题栈建树：遇 `level = L` 的标题，弹出栈内 `level ≥ L` 的节点，压入新节点，父节点 = 栈顶。
3. 层级跳变（H1→H3）：挂到最近的低层级标题下（不为跳级造虚拟 H2）。
4. 其他成卡块挂到栈顶标题；栈空则挂大卡片。
5. 段落/引用/普通列表挂到栈顶标题（栈空则大卡片）的 `own_block_indexes`。
6. 空卡片不生成（标题后紧跟同级/更高级标题时，该标题卡只含自身标题）。是否保留"空标题卡"作为导航锚点 ❓ O4。

### 2.4 稳定卡片 ID（✅ D4 已确认）

| 键 | 组成 | 用途 | 内容改动后 |
|---|---|---|---|
| `stable_key`（= `card_id`） | `path_hash` + `heading_path` + `kind` + `ordinal_in_parent` + 同名标题出现序号 | 布局匹配、detached/折叠锚点、跨刷新身份 | **不变** → 位置保留 |
| `content_hash` | 规范化文本 sha1 前 N 位 | 变更检测、渲染缓存失效 | 变 → 触发内容更新 |

**刷新匹配算法**：`stable_key` 精确匹配 → 失败则以 `(kind, content_hash)` 全文档重定位（应对标题改名/移动）→ 仍失败视为新增/删除。删除卡片的子卡片按新结构重归属。

**路径语义**：`path_hash` 仅用于选择快照文件；`stable_key` 内用文件名 + 文档首指纹 🔶。文件重命名/移动 → 提供"沿用旧布局"选项 ❓ O4。

### 2.5 布局持久化（✅ D9 + D15 已确认）

```
%APPDATA%\MarkdownCardWhiteboardReader\
  boards\<path_hash>\            # 每文档一个目录（D15：会话分片）
    <session_uuid>.json          #   本会话布局快照（含 schema_version）
    last_session.json            #   最近会话指针（跨进程恢复用）
  windows\<window_uuid>.json     # 每窗口状态：geometry、打开文档、active
  recent.json                    # 最近文件
%LOCALAPPDATA%\MarkdownCardWhiteboardReader\Cache\   # 渲染缓存、Web 资源、图片缓存
```

- 写入：临时文件 + `os.replace` 原子替换；`schema_version` 驱动一次性迁移。
- **同文档并发打开（✅ D15）**：每会话一份分片 + `last_session` 指针。打开时优先载入本会话分片；不存在则复制最近会话分片的**副本**（不共享，避免覆盖）。代价是布局不再跨窗口共享，与 FR-6.2"窗口完全独立"一致。
- 清理策略 🔶：窗口正常关闭时更新 `last_session`；孤儿分片按"最多保留 N 份/按时间淘汰"清理。

### 2.6 状态机（`detached` / `collapsed`）

| 状态 | 触发 | 几何行为 | 逻辑树 |
|---|---|---|---|
| `attached` | 初始 / 还原 | 受父卡约束；父卡移动则跟随（D8） | 正常 |
| `detached` | 右键"拖出为自由卡片" | 坐标转白板坐标，脱离约束，可自由拖动/缩放 | 保留 `parent_id` |
| `orphan_detached` | 父卡被删除/重归属 | 同 detached | 挂最近存活祖先 |
| `collapsed` | 折叠 | 子孙卡片隐藏，父卡收缩，**记忆其几何** | 不变 |

对齐内部架构约定：**分层 + 垂直切片 + Protocol 依赖倒置**；GUI 只做绑定；核心逻辑零 IO、零 GUI。

│   └── errors.py                # ParseError, LayoutCorrupted, DocumentMissing, DecodeError
├── application/
│   ├── ports.py                 # 全部 Protocol（见下）

## 4. 关键交互流程

**F1 打开文档**
选文件 → `MarkdownReader` 读字节（探测编码、归一换行）→ `BlockParser` → IR → `build_card_tree` → 查 `LayoutStore` 快照 → 命中则套用（含 `detached`/`collapsed`/viewport），未命中则 `layout_board` 生成线性布局 → 渲染可见卡片 → 写 recent。
异常分支：文件不存在 / 解码失败 / 解析异常 → 空布局 + 纯文本降级卡片 + 提示，**不崩溃**。

**F2 拖出为自由卡片**
右键子卡片 → 校验（已 detached 则菜单项禁用）→ 记录局部坐标 → 换算为**白板坐标**（含画布 scale 与祖先偏移）→ `detached=True` → 解除几何约束 → 父卡是否重排剩余子卡 ❓ O4 → 写快照。

**F3 拖动**
非 detached 子卡 → 位移 clamp 在父卡边界内；拖父卡 → 子卡跟随（D8），detached 子卡不动；拖动期间零重解析，仅移动 item；松手后写快照（拖动中不写盘，防抖 🔶）。

**F4 还原**
右键"还原到父卡片" → 按 `stable_key` 在父卡 `child_ids` 中定位插入位（按原文档顺序）→ `detached=False` → 重算几何 → 写快照。「收回所有子卡片」= 对全部后代执行 F4。「全部还原」= 清空 `detached`/`collapsed`/手动几何，`layout_board` 重建线性布局并重置 viewport（是否重置缩放 ❓ O4）。

**F5 刷新（验收 6 的核心流程）**
1. 重新读文件；失败 → 保留当前卡片树 + 报错，终止。
2. 重新解析 → 新 IR + 新卡片树。
3. 计算结构签名（大卡片数量、标题层级序列）并与旧签名比较 → 判定是否重大变化（D11）。
4. **非重大**：按 `stable_key` 匹配 → 命中则保留布局、仅按 `content_hash` 变化更新内容并失效渲染缓存 → 新增卡片按新顺序插入父卡 → 删除卡片移除、子卡重归属 → `detached`/`collapsed` 随 `stable_key` 保留。
5. **重大**：以新结构重建布局 + 显式提示（说明位置可能改变；是否提供"撤销"❓ O4）。
6. 落盘新快照 + 提示结果（更新/新增/删除/重建 各多少张）。

**F6 缩放/平移/适应视图**
滚轮 → 以光标为锚点应用 view transform（D7：卡片与文字一起缩放）；输入比例 → 以视口中心为锚点设置 scale；适应视图 → 全部卡片包围盒 + 边距。
✅ D14 解决 D7×D3 的交叉约束：Web 引擎只做**离屏渲染**（按 `content_hash` + 缩放档位缓存为图片），画布内是静态图片，可随 view transform 干净缩放；代价是公式/Mermaid 内容不可选中、档位切换时有重绘延迟。

**F7 多窗口（D10：多进程）**
新窗口 = 新进程 = 新 session → 独立 `BoardSnapshot` 分片、独立 viewport、独立 detached 状态 → 加载/切换文档。进程间**不共享**任何可变布局状态；跨进程窗口登记仅用于重启恢复。

**F8 关闭与恢复**
关闭窗口 → 写窗口状态 + 当前文档布局分片 → 重开:恢复 geometry + 打开文档列表 + active + 布局；分片损坏 → 丢弃布局重建 + 提示。

**F9 折叠/展开（D6）**
折叠标题卡 → 子孙卡片隐藏、父卡收缩到自有内容高度、子孙几何被记忆 → 展开按记忆还原位置；若期间发生过刷新，按 `stable_key` 重新匹配，未匹配到的新增子卡按线性规则落位。

**F10 目录跳转**
点击目录项 → 定位标题卡（居中 + 高亮）→ 若目标位于折叠祖先内 → 逐级展开 + 提示路径 → 视口平移（不改变 scale 🔶）。

## 6. 风险点

| ID | 风险 | 影响 | 缓解 |
|---|---|---|---|
| R1 | 卡片 ID 若含内容指纹会与"保留位置"冲突 | 改一个字即丢布局，验收 6 失败 | **已由 D4 解决**；写回归测试固定该行为 |
| R2 | QWebEngineView 与整体画布缩放（D3+D7）本不兼容：活 WebView 随 transform 缩放会糊、输入/命中偏移 | 若走活 WebView 方案，公式/Mermaid 在缩放下不可读 | **已由 D14 规避**（离屏图片 + 档位缓存）；仍须 spike 3 实测档位数量、重绘延迟与内存 |
| R3 | 多进程（D10）并发写快照的覆盖风险 | 静默丢布局 | **已由 D15 规避**（每会话分片、互不共享）；须验证分片目录的孤儿清理与 `last_session` 指针一致性 |
| R4 | 多进程内存与启动成本（每窗口一个 Python + Qt + 可选 WebEngine） | 3+ 窗口时内存压力明显 | 视口懒加载、离屏渲染缓存、文档级只读缓存按需 |
| R5 | 卡片体量过大（大卡片含整章自有内容） | 拖动/渲染退化 | 卡片高度上限 + 卡内滚动 + 视口懒加载（NFR-3） |
| R6 | 拖出瞬间坐标换算（局部↔白板，含 scale 与嵌套祖先） | 卡片跳位、层级换算错误 | **白板坐标是唯一几何真相**；进入拖出立即一次性转换；单测覆盖多级嵌套 |
| R7 | 父卡自适应高度与折叠收缩互相牵制 | 抖动、还原后位置漂移 | 明确定义父卡高度 = 自有内容 + 子卡包围盒（🔶）+ 折叠时使用记忆几何 |
| R8 | detached 卡片的父卡被删除/重归属 | 还原目标不存在 | §2.6 `orphan_detached` 规则 + 提示 |
| R9 | 刷新判据（D11）在"标题改名但层级不变"时判定为非重大 | 卡片按 `stable_key` 匹配失败 → 落到内容指纹重定位 | 已定义回退链；需表驱动测试覆盖改名/移动/重排 |
| R10 | 快照损坏 / schema 演进 / 用户手工编辑 JSON | 打不开或崩溃 | `schema_version` + 原子写 + 校验失败即降级重建 |
| R11 | 相对路径图片、远程图片、缺失图片 | 空卡片、卡顿 | `ImageResolver` 端口 + 异步 + 占位符；远程默认不加载 |
| R12 | 非 UTF-8 / BOM / CRLF / 超长行 | 乱码或解析异常 | 显式编码探测 + 降级纯文本卡片 |
| R13 | PyInstaller `--onedir` + Web 资源路径 | 交付形态启动即失败 | 交付形态下验证（不只在源码形态验证）；Web 资源显式打包 |
| R14 | 高 DPI × 画布缩放叠加 | 文字模糊、命中偏移 | spike 2/3 实机在 125%/150% 下验证 |
| R15 | 折叠语义若含糊会导致模型二次改动 | 返工 | **已由 D6 定死**；模型与单测先按此实现 |
| R16 | 只读承诺被缓存/日志文件破坏 | 违反产品边界 | `app_paths` 唯一出口 + 集成测试断言源目录零写入 |
| R17 | 100 卡片性能假设偏乐观（表格/Mermaid/公式为重渲染项） | 拖动卡顿 | 渲染缓存（`content_hash` 键）+ 视口懒加载 + 缩放档位截图 |
| R18 | 跳过 CLI 垂直切片直接上 GUI | 核心逻辑无法快速可验证 | 先 Typer CLI 切片跑通再包 GUI |
| R19 | 跨进程窗口登记（D10）若用文件实现 | 并发写损坏、恢复错乱 | 每进程独立窗口文件 + 唯一 `window_uuid`；启动清理孤儿登记 |

3. 打开方式：命令行参数、拖拽入窗、Windows 文件关联/右键"用本应用打开"。
4. 目录卡片来源：仅识别 `[TOC]`、无标记时自动生成、或两者并存且可开关。
5. 任务列表"只读渲染"是在所属卡片内渲染，还是单独成卡（现按需求原文单独成卡）。
6. 大卡片/标题卡是否显示自带标题栏文字（如首行摘要），以及空标题卡是否保留。
7. "全部还原"是否同时重置视口缩放与折叠状态。
8. 是否提供"撤销"（刷新重建后/全部还原后）。
9. "适应视图"的边距与最大缩放下限。
10. 连接线开关与默认可见性；远超视口时的降级策略。
11. 卡片内文本可选复制？跨卡片选择的预期表现。
12. 源文件被外部修改但未点刷新时，是否允许提示"文件已变化"（当前需求为无热更新，此提示是否越界）。
13. 日志与崩溃报告落盘位置（不得在 md 同目录）。
14. 是否需要代码签名与安装包（Inno Setup），MVP 是否只交付免安装目录。
15. 文件被重命名/移动时是否提供"沿用旧布局"（§2.4）。
16. 单文档规模上限与超限时的行为（如 > 2000 张卡片是否降级）。
